# ПОГРЕБОК-БОТ · аккаунты без аккаунтов

Бот принимает txt-экспорты плейлистов, хранит профиль человека и отдаёт ему
**персональную ссылку** на сайт. Сайт по ссылке подтягивает JSON профиля и становится
комнатой этого человека: мои треки ему не показываются.

Никаких паролей, OAuth и чужих API: только твой файл и твой chat_id.

---

## Что нужно от тебя (всё бесплатно, ~10 минут)

1. **Токен бота.** В телеграме: `@BotFather` → `/newbot` → скопировать токен.
2. **GitHub-аккаунт** (если ещё нет) и публичный репозиторий, например `pogrebok`.
3. **GitHub Pages** для сайта: настройки репозитория → Pages → ветка `main`, папка `/ (root)`.
   В корень репозитория положить `index.html` (это `reports/disco.html`).
4. **PAT-токен GitHub**: Settings → Developer settings → Personal access tokens →
   токен с правом `repo` (нужен боту, чтобы класть JSON профилей в репозиторий).

## Запуск бота

```bash
export POGREBOK_BOT_TOKEN="токен_от_BotFather"
export POGREBOK_GH_TOKEN="ghp_..."          # PAT с правом repo
export POGREBOK_GH_REPO="user/pogrebok"     # репозиторий с сайтом
export POGREBOK_SITE="https://user.github.io/pogrebok"
python pogrebok_bot.py
```

Бот пишет профили в `data/<chat_id>.json` и пушит их в `data/<chat_id>.json` репозитория.
Сайт читает их по `https://raw.githubusercontent.com/user/pogrebok/main/data/<chat_id>.json`
(raw.githubusercontent отдаёт CORS `*`, поэтому сайт может fetch прямо из браузера).

## Команды

| команда | что делает |
|---|---|
| прислать `.txt` | создаёт/обновляет плейлист профиля (имя = имя файла) |
| `/my` | персональная ссылка `site/?u=…` |
| `/add Артист - Трек [ссылка]` | добавить трек в первый плейлист; ссылка = полный трек; дубли ловятся без учёти регистра и пробелов |
| `/add! Артист - Трек` | добавить даже дубль |
| `/find Артист - Трек` | честная проверка: ✅/⛔ Apple(iTunes) и Deezer по каталогам + поисковые ссылки Яндекс/Spotify/YouTube/SoundCloud/Bandcamp |
| `/del N` | убрать N-й трек первого плейлиста |
| `/stats` | сводка профиля |

## Как сайт понимает ссылку

`index.html?u=<urlencode(raw-url-json)>` → сайт fetch'ит JSON `{files:[{name,tracks:[[a,t]]}],urls:{}}`,
строит из него профиль и рендерит всё как обычно: мозаика, маски, артисты, игры, плеер.
В drawer при этом горит «🌐 ПРОФИЛЬ ИЗ ОБЛАКА».

## Про прослушивание (честно)

Бот **не стримит каталог** — это было бы пиратством и мгновенным баном. Полное бесплатное
прослушивание живёт на сайте через официальные плееры: YouTube / SoundCloud / Bandcamp (по ссылке,
которую дал пользователь) + 30-секундные превью iTunes для треков без ссылки.

## Приватность

Профиль = список треков и виден всем, у кого есть ссылка (raw-URL угадываемый только по chat_id).
Не кидай туда ничего, что не показал бы другу. Хочешь приватнее — держи `POGREBOK_GH_REPO`
приватным и раздавай ссылки сам, либо убирай пуш в GitHub (бот продолжит работать локально).

## Локер: стримить СВОИ файлы через телеграм

Бот не раздаёт чужой каталог (это пиратство и бан). Но он умеет быть твоим личным облаком:

1. Пришли боту **аудиофайл** (mp3, который у тебя уже есть) — бот положит его в локер
   (хранится в твоём же TG-облаке, бот держит только file_id).
2. Бот ответит slug: `/play 6050b13eacbf`.
3. `/locker` — список локера. `/play SLUG` — стрим в телеграме.
4. На сайте у такого трека появляется кнопка **«▶ слушать в телеграме · твой локер»**:
   это диплинк `t.me/pogrebok_room_bot?start=play_SLUG` — бот пришлёт аудио в чат.

Профиль при этом получает поля `locker` и `bot`, сайт их подхватывает из JSON профиля.

## Статус «есть ли в Яндексе»

Публичного API поиска у Яндекс Музыки нет, поэтому сайт не утверждает «заблокирован».
Он честно сверяет трек с **твоим экспортом лайков**: зелёный бейдж «есть в твоей
Яндекс-библиотеке» или красный «в твоих выгрузках Яндекса не найдено» + альтернативы
(30-сек превью iTunes, TG-локер, эмбеды YouTube/SoundCloud/Bandcamp).

## Сайт как единственная точка входа (фоновый телеграм)

`pogrebok_server.py` поднимает ОДНИМ процессом: бота (фоном, в потоке), HTTP API
с CORS и, опционально, статику сайта. Токен живёт только на сервере — браузер его
никогда не видит.

```bash
export POGREBOK_PORT=8777
export POGREBOK_WWW=/путь/к/папке/с/сайтом   # опционально: тогда сайт лежит там же
python pogrebok_server.py
```

Сайт подключается к облаку ссылкой вида:

```
https://host/?bot=https://host&id=<chat_id>
```

После этого: профиль тянется с сервера при загрузке, а добавление трека на сайте
улетает POST /api/add и переживает устройства. В drawer горит «☁️ ОБЛАКО БОТА».

Эндпоинты: GET /api/ping · GET|POST /api/profile?id= · POST /api/add?id=
Проверено локально: ping → profile → add со ссылкой → profile обновился.

## Общая база сообщества (каталог)

Сервер ведёт `data/_catalog.json`: каждый трек, добавленный любым человеком
(через бота, сайт или /api/profile), попадает в общую базу с нормализованным
ключом `артист||трек` (регистр и лишние пробелы схлопываются, «Pyrokinesis» и
«pyrokinesis» — один исполнитель). Хранится: кто добавил (by), обложка (art),
ссылка на полный трек (url), альбом (album), комментарии (comments).

Эндпоинты:
- `GET /api/search?q=` — поиск по трекам и исполнителям общей базы;
- `GET /api/track?key=` — трек с альбомом и комментариями;
- `POST /api/comment?key=` — `{id,name,text}` комментарий в общую базу;
- альбомы: поле `albums` в профиле и в `/api/add` (`al`), отдельная сущность в каталоге.

Сайт в режиме облака (`?bot=&id=`) показывает в поиске меню результаты общей базы
с пометкой ☁️, а на странице трека — комментарии других людей и форму «сказать».
Если трека нет ни у тебя, ни в базе — поиск предлагает «＋ предложить в базу».

## Про тексты песен (Genius)

Полные тексты встраивать нельзя (копирайт), и API Genius тексты не отдаёт —
только метаданные. Поэтому на странице трека стоит честный чип «Genius · текст»
(поисковая ссылка). Опционально: задай `POGREBOK_GENIUS_TOKEN` (client access
token, бесплатно) — сервер сможет обогащать каталог метаданными Genius
(альбом, обложка альбома, фото артиста) для треков, добавленных в базу.

## ВАРИАНТ БЕЗ ДОМАШНЕГО СЕРВЕРА: Cloudflare Workers (вебхуки)

Если домашняя сеть не пускает к api.telegram.org (winerror 10060 / таймауты),
бот живёт в облаке CF: телеграм сам стучит на вебхук, профили лежат в KV,
сайт ходит в то же API. Бесплатно, 24/7, вне твоей сети.

1. dash.cloudflare.com → регистрация → **Workers & Pages → Create → Hello World worker**,
   имя `pogrebok` → Deploy.
2. Worker → **Edit code** → удалить всё → вставить содержимое `worker.js` → **Save and Deploy**.
3. Worker → Settings → **Variables and Secrets**:
   secret `TG_TOKEN` = токен BotFather; переменные `BOT_USER=pogrebok_room_bot`,
   `SITE=https://chmoshnik187.github.io/pogrebok`, опционально `GENIUS`.
4. Workers & Pages → **KV** → Create namespace `pogreb`; затем Worker → Settings →
   **Bindings** → Add: variable `POGREB` → namespace `pogreb` → Save.
5. Скинь автору погреба URL вида `https://pogrebok.<sub>.workers.dev` —
   он пропишет вебхук (`/tg`) со своей стороны и проверит /api/ping.
   Домашний bot.py при этом не запускай: вебхук и getUpdates конфликтуют (409).

API воркера совпадает с pogrebok_server.py: /api/ping /api/profile /api/add
/api/search /api/track /api/comment. Сайт подключается тем же
`?bot=<worker-url>&id=<chat>`.
